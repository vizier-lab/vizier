# Data Model: Pluggable Storage

No domain entity changes meaning. Every existing table exists on both backends with the same name, columns and keys (encryption AAD binds table names, R10). This document lists only what is new or differs.

## Logical column types (both backends)

| Logical | SQLite | PostgreSQL |
|---|---|---|
| integer (ids, ms timestamps, counts, booleans) | `INTEGER` | `BIGINT` |
| real | `REAL` | `DOUBLE PRECISION` |
| text, JSON documents | `TEXT` | `TEXT` (cast to `jsonb` only inside `Dialect::json_*`) |
| bytes | `BLOB` | `BYTEA` |
| autoincrement id | `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |

Booleans stay integers (0/1) on PostgreSQL so row mapping is shared.

Every PostgreSQL text column is `COLLATE "C"`, so ordering, comparison and uniqueness are byte-wise like SQLite's `BINARY` collation regardless of the database locale.

## New: `rowid` (PostgreSQL only)

`message_reaction`, `client_tool_call`, `question_set`, `sensitive_ask` and `agent_secret_event` have `rowid BIGINT GENERATED ALWAYS AS IDENTITY`, standing in for SQLite's implicit rowid, so the `ORDER BY …, rowid` insertion-order tie-breaks read the same on both backends.

## New: `vizier_schema_migrations` (PostgreSQL only)

| Field | Type | Rules |
|---|---|---|
| `version` | BIGINT PK | File number `NNNN` |
| `name` | TEXT | File stem |
| `applied_at` | BIGINT | ms |

Applied in order under `pg_advisory_xact_lock(hashtext('vizier_schema'))`. Startup refuses a database whose highest version is newer than the binary knows (`schema_incompatible`).

## Changed: `session_history.seq`

PostgreSQL: `BIGINT GENERATED ALWAYS AS IDENTITY`, unique. SQLite: unchanged (`MAX(seq)+1` inside the write transaction).

## Not ported: `memory_fts`

SQLite's FTS5 table and its triggers index only the legacy flat `memory` table, which nothing queries any more (memory search goes through passages and vectors). PostgreSQL gets no full-text equivalent.

## New: `document_index_d<N>` (PostgreSQL)

| Field | Type |
|---|---|
| `context` | TEXT |
| `path` | TEXT |
| `embedding` | `vector(N)` |

Index: `USING hnsw (embedding vector_cosine_ops)`; `(context, path)` btree for deletes.

## New: blob keys

`BlobStore` keys are relative, `/`-separated, validated (no `..`, `.`, empty or backslash segments):

| Data | Key |
|---|---|
| Upload | `uploads/<file_id>/<filename>` |
| Artifact version | `artifacts/<agent_id>/<artifact_id>/content.v<n>` |
| Memory document | `agents/<agent_id>/memory/<bundle>/<path>.md` |

`LocalBlobStore` maps a key to `<workspace>/<key>` — exactly today's paths, so existing workspaces need no file move. `S3BlobStore` maps it to `<prefix>/<key>` in the bucket.

`BlobMeta { key, size: u64, etag: Option<String>, modified: Option<DateTime<Utc>> }`.

## New: `storage_migration` (destination PostgreSQL)

| Field | Type | Rules |
|---|---|---|
| `id` | TEXT PK | UUID |
| `source_fingerprint` | TEXT UNIQUE | SHA-256 of source db file header + table row counts + workspace path |
| `phase` | TEXT | `schema`, `tables`, `vectors`, `blobs`, `verify`, `done`, `failed` |
| `cursor` | TEXT | JSON: current table and last copied key, current blob key |
| `report` | TEXT | JSON counts/bytes/checksums; no content, no secrets |
| `started_at`, `updated_at`, `finished_at` | BIGINT | ms |

A `done` row for the same fingerprint refuses a second run unless `--reset-destination`. Tracked in #82 with the command.
