## Content rules

1. **ID** = `LV-ST-<STATE>`; one row = one state = one claim that can be tested.
2. **"what passing looks like"** must be translatable into *a step + an expected result*. If it
   says "looks fine", the row is not finished.
3. **`error` is split in three**, not one row: `error-validation` (422), `error-forbidden` (403),
   `error-transient` (5xx/timeout, retry must be idempotent). For this row the 422 split is still
   argued — see O1; the row is `LV-ST-NO-SPEECH` until another decision is made.
4. **`indistinguishable`** — if two state rows are answered by an identical response, mark it in the data
   column. That is a finding, not a scribble: the choice is a new API field or merging states in the UI,
   and either one has to be decided knowingly.
5. **An open row must have an owner** — `open -> PIC + date`. An open question without an owner's name
   is not an open question, it is debt.
6. **Exploration boundary** — a flow that is not fixed yet: a gap in states is an open question, not a defect.
7. **Zero point** — while `spec_ref`/`design_ref` are not versioned, this document is a draft; it may not
   be used to declare "failing".
